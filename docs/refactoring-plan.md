# План рефакторинга mif-boat-safe

Карта работ: этапы, их цели, порядок задач и зависимости между ними.

Спецификация каждой задачи — проблема, где в коде, критерии готовности,
решения по ходу работы — живёт в её issue на GitHub. Здесь у задачи только
одна строка и ссылка. Если задача меняется, правится issue, а не план.

Номера вида «2.1» — номера задач в плане. Описания в issue ссылаются на
задачи этими номерами («зависит от задачи 3.1 плана»); по таблицам ниже
номер переводится в issue.

## Как пользоваться

- Порядок этапов важен. Внутри этапа задачи берутся в любом порядке, если
  не указана зависимость.
- Одна задача = одна ветка = один PR в `dev`, слияние через squash.
- Чтобы дать задачу Claude Code: «Выполни issue #32». Процесс работы и
  остановка перед коммитом описаны в `CLAUDE.md`.
- План меняется, когда задача выполнена (отметка в таблице), добавлена
  новая задача (строка в таблице) или меняется порядок этапов.

## Этап 0. Порядок в репозитории — готов

Ветки `main` и `dev` синхронизированы и защищены rulesets; CI (pytest,
ruff, Bandit, pip-audit); доступы через команды; шаблон PR; метки, типы
задач, milestones.

Договорённости:

- PR с задачами идут в `dev` и сливаются через squash;
- `dev` → `main` сливается только через merge commit, изменения идут
  только в эту сторону;
- `Closes #N` в PR в `dev` задачу не закрывает (ветка по умолчанию —
  `main`): задачу закрывают вручную после слияния.
